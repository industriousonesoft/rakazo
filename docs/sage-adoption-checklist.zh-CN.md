# Sage 理念移植实施 Checklist

状态：尚未开始业务实现。下面所有未勾选项表示未来工作，不表示本次文档交付未完成。

先读 [ROI 评估](./sage-adoption-roi.zh-CN.md) 与 [移植方案](./sage-adoption-design.zh-CN.md)。对象为 Rakazo 内部机器人；首期同时实施编程和 CSV 报表两个试点。

执行约定：每个条目完成后记录提交或测试报告引用；不得仅凭模型自述勾选。阶段退出条件未满足，不进入下一阶段。阶段 0–4 为首期；阶段 5 为后期可选项，未实施不影响首期完成。负责人是职责角色，实施时分配给实际维护者，不在公开文档记录个人账户信息。

## 阶段 0：建立基线（3–5 人日）

负责人：方案实施者与评估维护者。

- [ ] **确认代码基线**：复查 Run 收尾、Pi 工具执行、审批和评估框架；产出与文档差异清单。
- [ ] **定义两个受信模板**：固定源码检查范围/命令和 CSV 数据规则；产出版本化配置，模型不可修改必需条件。
- [ ] **建立 20 个合成场景**：按方案各 10 个；产出独立裁判与干净状态初始化器。
- [ ] **准备真实 shell 环境**：确认命令实际运行、退出码可观察；使用真实 sandbox，不接受模拟成功。
- [ ] **建立 A/B/C 对照配置**：现有行为、Skill、Skill 加门禁；固定模型、预算和执行顺序。
- [ ] **记录基线**：保留当前可执行组的结果；C 组待实现后执行，未运行不能填为通过。
- [ ] **建立成本记录表**：记录开发时间、人工核验、返工、推理和误阻断处理；不可用数据填未知。

退出条件：场景可重复，裁判不依赖 Agent 的完成声明，无生产数据或生产外部操作。

## 阶段 1：验证基础设施（6–10 人日）

负责人：后端与数据库实施者。

- [ ] **增加共享契约**：覆盖模式、规则引用、三态结果和证据摘要；类型检查通过，供应商无关。
- [ ] **增加持久化及迁移**：证据归属 Run，旧记录未启用；验证迁移与兼容读写。
- [ ] **绑定受信规则快照**：服务端校验调用者及空间权限；模型不能降级模式或改写规则。
- [ ] **接入权威执行路径**：证据必须等待写入；审计回调失败不再被误当作验证完成。
- [ ] **支持根代理和子代理**：父任务验证实际产物，不信任子代理的文字结论。
- [ ] **处理后台 shell**：启动、运行、结束分别建模；未结束不得通过。
- [ ] **实现版本与并发控制**：冻结快照和摘要绑定；同工作区协调；并发改动不会复用旧证据。
- [ ] **实现有限修正**：最多两轮，持久化计数；取消、超时和任务预算优先停止。
- [ ] **接入全部最终完成分支**：质量状态和正式交付在完成事务中校验，包含空回复与恢复路径。
- [ ] **保留既有安全语义**：审批拒绝、请求绑定、受控副作用去重回归通过。
- [ ] **实现能力不足处理**：不支持的运行时返回无法验证，不伪装通过。

退出条件：伪造、缺失、过期或写入失败的证据均不能产生“验证通过”；旧任务可正常执行。

## 阶段 2：两个验证器（6–10 人日）

负责人：验证器实施者与场景维护者。

- [ ] **编程检查**：在所属 sandbox 的冻结快照执行受信测试命令；记录真实退出码、规则和源码摘要。
- [ ] **防止空测试及测试篡改误通过**：独立验收测试不可由模型修改；不存在的测试判为无法验证。
- [ ] **CSV 检查**：固定格式，核对字段、日期、重复/遗漏、精度及汇总；产出可定位诊断。
- [ ] **绑定输入和产物**：源数据快照不可替换；最终附件必须是检查过的版本。
- [ ] **明确出口范围**：试点只生成隔离产物；未控制 shell/GUI 外部出口的环境不声称全面交付门禁。
- [ ] **启用观察模式**：记录建议判定与开销，确认不改变原有交付结果。
- [ ] **启用试点强制模式**：通过、失败、无法验证及修正后通过均能演示。
- [ ] **共享结果展示**：Web/Electron、移动端和消息渠道结论一致；详情按需展示。
- [ ] **验证回退**：关闭模式恢复原有行为，已有证据仍可查询，旧数据不变为通过。

退出条件：两个验证器各自通过 10 个场景的确定性机制检查；模型是否能完成任务另行统计。

## 阶段 3：故障、兼容与灰度（5–8 人日，含阶段 4 的评估整理工作）

负责人：测试维护者与发布维护者。

- [ ] **伪造完成**：没有实际检查，仅声明“测试通过”，不能产生系统认证。
- [ ] **失败与缺失能力**：非零退出码、超时、验证器缺失、源数据缺失分类正确。
- [ ] **版本失效**：检查后修改、旧证据、子代理替换附件均被发现。
- [ ] **并发与恢复**：多代理写入、Worker 重启、租约失效、重复事件不产生错误认证。
- [ ] **事务与权限**：证据写入失败不能通过；跨 Space 不可读写；密钥和原始敏感结果不进入证据摘要。
- [ ] **修正边界**：额度耗尽、取消、任务预算耗尽不会无限重试或伪装完成。
- [ ] **审批回归**：质量通过不能绕过审批；拒绝的动作不会通过修正循环重放。
- [ ] **兼容回归**：未启用任务、静默任务、委派返回和消息渠道保持明确语义。
- [ ] **离线测试**：运行受影响单元、Pi 协议和数据库集成测试；记录范围及结果。
- [ ] **跨端验收**：验证现有详情中的质量状态；UI PR 补 CI 页面截图；Electron E2E 由 CI 执行。
- [ ] **观察后灰度**：先限定模板和工作区，再启用强制模式；记录开关与回退演练。

退出条件：安全和状态回归无未解决问题，受控路径没有无有效证据的系统认证。

## 阶段 4：实测 ROI 与投资决策

负责人：评估维护者与产品维护者。

- [ ] **完整运行三组实验**：显式启动 180 次真实模型试次；付费运行不加入默认 CI。
- [ ] **核对试次归因**：未运行、环境故障、供应商错误和产品失败单列，不能计为通过。
- [ ] **独立判断完成声明**：按统一规范盲态复核自然语言；系统认证与模型夸大分别统计。
- [ ] **分场景报告收益**：各类分别给出合格率、错误完成率、误阻断率、延迟、费用与人工时间。
- [ ] **比较 C 对 B 的增量**：确认收益来自机械门禁，而不只是更详细的 Skill。
- [ ] **复算回本**：使用实测任务量与成本；未知数据和样本局限明确列出。
- [ ] **应用投资门槛**：错误完成率相对 A 下降至少 50%、误阻断不超过 5%、合格率不下降且净收益为正；记录是否满足。
- [ ] **处理零基线或不稳定结果**：补充代表性样本，不能无依据宣布质量提升。
- [ ] **确定继续、缩小或停止**：仅一类受益时只扩大该类；净收益不足时停止扩展。
- [ ] **指定持续维护职责**：规则版本变更触发回归；定期复核无法验证原因和误阻断。

退出条件：发布范围有测量依据，未覆盖能力有明确说明，回退可执行。

## 阶段 5：独立审查（可选，新增 5–9 人日）

负责人：后端实施者、评估维护者与产品维护者。启动前提：阶段 4 已完成，维护者确认存在机械门禁未覆盖且值得投入的质量问题。默认关闭，不要求为首期补做本阶段。

- [ ] **确认投资依据**：列出目标遗漏、任务范围及新增预算；记录实施或暂缓决定。
- [ ] **增加受信启用配置**：任务模板决定是否必需审查；执行者不能自行关闭，旧任务默认关闭。
- [ ] **建立新上下文审查**：提供原始要求、冻结产物与系统证据，复用临时子代理及现有审查 Skill。
- [ ] **落实权限限制**：后端限制读取范围，禁止任意 shell、写连接器和进一步委派；检查在隔离副本运行。
- [ ] **增加版本化审查记录**：区分需求符合性和质量结论，保存依据、问题及来源；不另建 manifest。
- [ ] **绑定最终交付**：必需审查缺失或有阻断项不能认证通过；机械失败不能被 AI 审查覆盖。
- [ ] **落实修正职责**：执行者修改、审查者复查；与机械验证共用两轮修正额度，版本变化使旧结论失效。
- [ ] **覆盖异常与绕过测试**：跳过、越权、旧证据、超时、非法输出、重启、重复结果和假阳性均有回归。
- [ ] **完成跨端呈现及回退**：只对启用任务显示审查结论；关闭只影响新 Run，不能静默豁免进行中任务。
- [ ] **运行 C/D 对照**：两类各 5 个固定复杂场景、每组 3 次，共 60 次额外试次；不混用不同时期基线。
- [ ] **评估新增收益**：核实真实缺陷、误报、修正引入问题、人工时间与费用，不以发现数量评价质量。
- [ ] **决定启用范围**：按新增 ROI 门槛扩大、限定某类或保持关闭，并记录维护职责。

退出条件：权限与证据回归通过；新增质量收益及成本满足 ROI 报告门槛才扩大。未满足可结束实验并保持关闭，不能标记为已证明有效。

## 验证入口与结果记录

以下为后续实施的测试入口，不代表本次已经运行：

```bash
pnpm test:pi
pnpm test:integration
pnpm test:evals --list
```

先运行受影响的定向测试，再按实际改动选择上述测试层。真实 sandbox 与付费评估入口遵循 [Agent verification](./agent-verification.md)，新增试点选项需随实现更新文档，不能假定当前 CLI 已支持质量门禁三组实验。

每阶段记录模板：

| 项目 | 填写内容 |
| --- | --- |
| 代码与规则版本 | 提交标识、规则版本 |
| 验证范围 | 场景、模型配置、环境能力 |
| 结果 | 通过/失败/未运行计数，诊断报告引用 |
| 成本 | 开发时间、人工处理、推理与耗时 |
| 残留限制 | 未覆盖出口、格式、运行时或任务类型 |
| 决策 | 进入下一阶段、缩小范围或停止 |

公开记录只使用合成数据与可公开标识，不包含个人路径、账户、私有地址或密钥。
